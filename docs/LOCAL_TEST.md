# 临时服务验证

使用本地构建或 Release 生成的二进制，在独立测试目录运行。管理前端已嵌入二进制，运行时不需要 Node.js。

在放置二进制的目录执行：

```powershell
$env:CODEX2API_OAUTH_BIND = '127.0.0.1:8080'
$env:CODEX2API_ADMIN_BIND = '127.0.0.1:8081'
$env:CODEX2API_USER_BIND = '127.0.0.1:8082'
$env:CODEX2API_API_BIND = '127.0.0.1:8083'
$env:CODEX2API_PUBLIC_OAUTH_URL = 'http://127.0.0.1:8080'
$env:CODEX2API_PUBLIC_ADMIN_URL = 'http://127.0.0.1:8081'
$env:CODEX2API_PUBLIC_USER_URL = 'http://127.0.0.1:8082'
$env:CODEX2API_PUBLIC_API_URL = 'http://127.0.0.1:8083'
$env:CODEX2API_DATABASE_URL = 'postgresql://codex2api:password@127.0.0.1:5432/codex2api_test'
$env:CODEX2API_REDIS_URL = 'redis://127.0.0.1:6379/0'
.\codex2api.exe
```

启动前需要准备独立的 PostgreSQL 测试数据库和可访问的测试 Redis；缺少配置或连接失败时服务不会启动。默认键前缀由 PostgreSQL 主机、端口、库名及 schema生成，自动化用例的不同临时数据库不要共用手工指定的前缀。

测试库首次管理员为 admin/admin。通过管理页授权供应账户、配置模型和套餐、创建用户、发放订阅并配置套餐号池。
已有人工价格、停用和删除状态应保留；有完整预设的新支持模型应自动出现并启用。

```powershell
Invoke-RestMethod http://127.0.0.1:8080/healthz
Invoke-RestMethod http://127.0.0.1:8080/version
```

核对 package_version、release_commit 与仓库版本常量一致。Ctrl+C 停止服务；重新运行保留该测试库。
测试必须使用独立 PostgreSQL 数据库，不得连接正式库。

ccodex 内置正式服务根 `https://oauth-ai.alsl.xyz/v1/chatgpt`，需经该域名的反向代理接入测试实例，再检查浏览器/设备码登录、模型和额度读取、连续两轮生成、
取消及客户端重连。使用实际反向代理入口时配置 CODEX2API_PUBLIC_OAUTH_URL 并启用 WebSocket；
该环境变量只声明地址，不自动提供 TLS。检查号池内授权失效和配额耗尽时输出前自动换号，号池耗尽的结构化错误，以及已输出后不重放的边界。

检查用量记录中的实际模型、错误、上游 request ID 和费用快照。未知价格、未报告用量及
[未实现能力](ARCHITECTURE.md#client-routes-and-capability-boundaries)不能用假成功代替。

测试只为精确计价、鉴权隔离、并发调度、协议解析等关键算法和业务约束编写。常量重复、普通 UI 结构、必填字段／序列化、简单字段映射和 CRUD 不编写自动化测试；已有的非关键或冗余测试可以删除，不为追求套件全绿而保留、修补它们。

遇到断言失败，先确认它保护的业务约束及当前契约，再判断是实现缺陷、无效测试数据还是过时断言。实现缺陷修实现；测试数据或预期只有在当前契约支持时才修改。禁止机械迎合断言、放宽正式校验，或将相关关键失败未解决的任务报告为完成。

普通改动按影响范围执行对应前端的 lint、typecheck、build 或 `cargo check -p <crate> --locked`。纯文档改动检查文档及差异即可。Windows 可使用已安装的 MSVC 工具链，或同版本 Rust GNU 工具链加 MinGW。浏览器交互按实际改动人工核对，钱包数据只在独立测试库通过管理端余额调整准备。
数据库校验使用当前 schema 和种子数据，并覆盖启动迁移的事务回滚、版本记录及重复启动跳过已执行迁移。

## 前后端开发启动

前端热更新使用两个 `pnpm dev` 进程；Rust 用 `cargo run -p codex2api --features dev-frontend`。
此显式开发特性只运行四个后端接口入口，跳过静态前端导出及其源码清单校验，页面由 Next 开发服务器提供。
它不能用于 release 构建；默认构建仍严格嵌入并校验两个静态前端。

Rust 设置 `CODEX2API_PUBLIC_USER_URL=http://127.0.0.1:3001`；管理前端在 `frontend/` 运行
`pnpm dev --hostname 127.0.0.1 --port 3000`，用户前端在 `frontend-user/` 运行
`pnpm dev --hostname 127.0.0.1 --port 3001`。对应后端默认端口为 8081 和 8082，OAuth 客户端入口为 8080，AI API 网关为 8083。
Windows GNU 工具链可显式使用 `cargo +1.93.0-x86_64-pc-windows-gnu run -p codex2api --features dev-frontend`，并将 MinGW 的 bin 目录加入 PATH。


用户登录经 Next 同源代理转发时，浏览器的 `Sec-Fetch-Site: same-origin` 保留浏览器入口语义；后端允许该同源请求或与 `CODEX2API_PUBLIC_USER_URL` 精确匹配的 Origin，并拒绝 cross-site。受保护的写入另行校验 CSRF。访问 3000、3001 的根路径分别跳转 `/admin/`、`/user/`。

鉴权回归覆盖两端真实 JWT 互换、同密钥不同用途、错误账户类型、未知 kid、过期/撤销、篡改签名，以及 none、空算法、HS256、非 RS256 算法的拒绝。带错误 Bearer 和有效 Cookie 的请求仍须失败。`accounts` 的账户类型与资料表归属不可更改；用户侧数据仓库不得暴露供应账户查询。Codex OAuth 的客户端协议、签名密钥、设备授权和令牌与网页登录 JWT 独立。

用户端页面为 `/user/`（总览）、`/user/usage/`（使用信息）、`/user/subscriptions/`、`/user/plans/`、`/user/orders/`、`/user/wallet/`、`/user/devices/`、`/user/profile/`（用户信息）。检查桌面侧栏折叠和手机抽屉、面包屑及头像入口；直接进入或刷新子页先恢复会话，确认未登录后才显示登录表单。总览数值应与本人对应明细一致，资料页只展示本人的信息，修改密码仍要求当前密码。

用量记录统一在 `/admin/usage/` 和 `/user/usage/`，API 与 OAuth 请求共用列表、详情和统计。AI API 网关页面为管理端 `/admin/api-groups/`、`/admin/api-keys/`，用户端 `/user/model-market/`、`/user/api-keys/`。配置标签与模型后，核对只有勾选的模型可用、模型列表不随标签支持范围变化、执行仍限定在所选标签号池、模型倍率覆盖组倍率、组与模型的每用户并发和 RPM 同时生效，多把 Key 不能增加同一用户的限额。模型广场默认展示基础目录，横向切换组后展示精确计费价格和两层限制。密钥只在创建时返回一次，撤销后调用立即失效；钱包 API 扣款不能改变 OAuth 订阅额度。

管理前端的布局、表单与失败反馈在隔离服务上按需人工检查。真实平台授权、订阅权限及生成行为使用获准的供应账户单独验证。

购买与订单检查：关闭套餐的“允许购买”后，用户目录移除该套餐，管理员仍能在订阅管理中直接分配。仅开启且已配置售价的套餐展示，未定价或关闭购买的套餐不得出现在用户列表和总数中；直接调用预览、沿用旧预览确认、支付旧待付款订单也必须被拒绝且不扣款。点击下单只打开预览，关闭或反复计算后订单数、钱包、订阅和优惠券预留数均不变。“使用优惠码”在空输入或全空格时禁用，填写后才可提交；移除优惠码恢复原价。支付方式直接显示钱包可用余额。预览过期时使用独立的“刷新预览”，不能自动下单；确认前展示最终费用、支付方式、套餐和有效期。点击“确认订单”才产生一条待支付订单，重试确认复用原单，然后单独执行钱包支付，最后显示完成状态。支付成功后订单、余额、订阅和钱包记录一致。按原价 $30/30 天、剩余 15 天升级至 $60/30 天的报价应为新剩余费用 $30、抵扣 $15、应付 $15，原到期时间不变。核对不同时期续费价格、管理员发放快照、改价后抵扣不重算、降级在到期前被拒绝，以及重复支付、跨用户订单、过期报价和取消订单不扣款。管理端 `/admin/orders/` 查看相同的费用快照与支付状态。

优惠券检查包括不存在、未生效、过期、停用、门槛不足、套餐不符、个人 / 全局次数用尽、并发确认最后一个名额、取消与到期释放、已确认后修改规则、零元应付和重复支付。管理端 `/admin/coupons/` 可维护规则，订单明细保留原优惠。用户错误提示应区分余额不足、套餐关闭、订阅变化与订单过期。预览签名不可篡改、跨用户重用或充当会话 JWT；用户端不能访问优惠券管理。

使用信息检查应在独立测试库中准备两位用户及各自独立订阅的真实格式账本，分别核对汇总、总览日期图表、筛选、分页和额度窗口只含本人数据；使用信息页保留明细，不重复显示图表；供应账户名称、凭据、路由、原始错误与上游请求编号不能出现在响应中。未报告费用 / Token 保持未知；空日期仅在查询成功后补零。覆盖首次加载、空账本及零匹配筛选；东八区、UTC 与负时区均须返回有效空汇总 / 数组，日期 SQL 不得把减去负偏移写成注释标记。

完成相关修改后集中运行最小范围的必要检查；没有新改动、失败或明确未解决的风险，不重复运行测试，也不扩大到无关套件。禁止编译或启动服务的会话只做获准的源码及数据库检查，不声称运行时验证完成。


订单、订阅与用量筛选需组合用户和套餐条件，核对总数、分页与全部匹配行；用户订单的套餐候选和记录均不能包含其他用户内容。检查停售套餐仍在历史订单候选中，订阅默认隐藏到期记录，用户搜索支持用户名 / 名称 / 邮箱，空结果和清除选择可恢复全部记录。

余额调整检查原因省略、null、空字符串和全空格，以及正向、负向、超额减少、并发支付、身份旧版本拒绝及同请求重放；并发钱包变动不能导致相对调整版本冲突，余额必须与新增系统流水同时成功或同时回滚，不能删除或修改流水。用户响应中不得出现操作人和管理原因。概览用两位用户、多条当日请求、昨日记录及多个独立订阅用量验证活跃用户去重和本地午夜边界；正常订阅数须排除停用及到期账户。

流水管理联合检查用户名、来源和时间范围筛选，核对总数与分页一致、开始包含 / 结束排除、空结果、同一时间多笔流水的顺序，以及历史订单支付和可空原因的系统操作同时可见。仅管理会话可访问全站流水；用户接口仍只返回本人流水，不显示管理操作人和原因。金额及记录不可改写或删除。

账户存储和业务隔离：Rust 回归在真实 PostgreSQL 中验证钱包并发、订单幂等、数据库约束、新用户无订阅和同平台多订阅。验证 `/subscriptions/{id}` 的配置、设备、路由、用量和记录均校验订阅归属。续费和升级必须指定目标订阅，另购应创建独立 ID；套餐限流默认为 RPM 40、并发 10，订阅覆盖与继承分别验证。

Rust 数据库回归必须设置 `CODEX2API_TEST_DATABASE_URL`，使用有建 schema 权限的专用测试数据库。每个临时 fixture 创建独立 schema，释放后删除该 schema；没有内存数据库替代实现。

```powershell
$env:CODEX2API_TEST_DATABASE_URL = 'postgresql://codex2api:password@127.0.0.1:5432/codex2api_test'
$env:CODEX2API_DB_MIN_CONNECTIONS = '0'
$env:CODEX2API_DB_MAX_CONNECTIONS = '4'
```

按改动选择 `cargo test -p <crate> <关键用例过滤条件>`；不默认执行全工作区测试。

实际 Desktop app-server 的 SSE 错误与搜索计费联调用例默认忽略。设置 `CODEX2API_TEST_CLI` 为已安装客户端的原生可执行文件后，使用 `cargo test -p codex2api-oauth --lib installed_desktop_ -- --ignored` 单独运行；未配置客户端不能视为通过联调。
