# 管理界面

管理网页位于 `frontend/`，用户中心和 OAuth 确认页位于独立的 `frontend-user/`。两个 Next.js 项目分别导出，由 `codex2api-admin` 和 `codex2api-user` 各自嵌入单个 Rust 可执行文件，并由各自端口提供。运行服务不需要 Node.js，也不读取外部前端目录。

## 组件和布局

App Router 路由目录只保留页面入口，列表、详情、弹窗与业务子视图分别使用独立组件文件，统一放在 `src/app/components/<业务>/`；对应的数据模块放在 `src/app/data/<业务>/`。例如供应账户的视图集中在 `src/app/components/suppliers/`，数据逻辑集中在 `src/app/data/suppliers/`，不在列表或详情路由下嵌套 `_components/`、`_data/`。跨页面共享的业务组件放在 `src/components/`，共享表单放在 `src/components/forms/`，基础控件仍在 `src/components/ui/`。管理端和用户端遵循相同目录规则。

视图与数据分开：业务专属的数据读取、编辑状态、校验和提交放在 `src/app/data/<业务>/` 的 hook 中；通用请求、DTO 和共享业务 hook 放在 `src/lib/`。视图绑定 hook 返回的值与操作，数据模块不导入业务视图。React 状态更新驱动重渲染，状态按页面或组件实例隔离；会话与通用操作状态按原有用途共享。供应渠道的请求配置与渠道组件注册分开，数据模块只依赖请求配置。响应式布局留在视图组件中，保持已有手机表格、侧栏抽屉及弹窗滚动行为。

数据层按业务集中维护，同一业务的读取、提交、状态与类型可以位于一个 `index.ts`，不按每个组件或 hook 机械拆文件。后端同样按业务职责分模块，简单资源在一个 Rust 文件中维护路由和处理函数，不额外套 `mod.rs`、`handlers.rs`。共享只用于行为与权限语义一致的部分。

所有交互控件使用项目内的 shadcn/ui 组件源码，基础样式由 Tailwind CSS 提供。官方组件源码位于 `frontend/src/components/ui/`。业务页面直接导入官方组件。请求、表单校验、错误通知和记录映射属于不渲染界面的业务逻辑，放在对应业务数据模块或共享的 `src/lib/` 中。禁止重新引入自定义控件和手绘组件样式。

管理壳采用官方 `sidebar-07` 的结构，包含侧栏、顶部导航和内容区。菜单按工作台、用户与订阅、交易管理、供应资源、系统配置分组；套餐、订单、流水和优惠券放在交易管理，供应账户、标签和代理放在供应资源。保留紧凑的默认控件尺寸、短间距和表格密度；主内容区不重复显示页面标题和说明卡片，刷新、表格／卡片切换及创建等操作全部放在上方筛选栏。桌面可折叠侧栏；窄屏通过抽屉导航。供应账户和订阅保留各自的业务边界，列表提供筛选以及表格／卡片视图。详情使用横向标签页，长表单使用官方 ScrollArea 在弹窗正文中滚动，标题和操作区保持可见。用户端不使用管理员壳或管理接口，OAuth 页面属于用户端。

用户壳与管理端采用同样的 shadcn Sidebar、顶部面包屑、主题菜单及紧凑内容区，代码和接口分别维护。侧栏按工作台、订阅服务、账户分组，工作台包含总览、使用信息和模型广场；订阅服务包含我的订阅、购买套餐和我的订单；API 服务提供 API 密钥；账户包含钱包、登录设备和用户信息；桌面折叠为图标，手机使用抽屉，选择页面后收起抽屉。各栏目使用独立路由，共享用户会话布局，站内导航不重新登录，刷新保留当前地址并先恢复会话。OAuth 确认页独立于此布局。

用户总览展示本人钱包余额、请求数、Token 与已计费用量，逐项展示各订阅及期限、当期额度窗口；不把免费 / 付费统计成两份订阅。总览提供最近 1 / 7 / 30 天的请求与 Token 趋势、计费用量趋势，以及最近订单。使用信息页 `/user/usage/` 提供平台、模型、结果与时间筛选、数值汇总和分页明细，图表统一保留在总览，显示实际输入 / 输出、缓存、推理、费用与耗时。数据仅来自本人的本地账本，模型费用是套餐额度用量，与钱包支出分开。未知 Token / 金额显示“—”并报告缺失次数；只有确实没有请求的日期补零。用户信息页 `/user/profile/` 展示用户名、名称、邮箱、启用状态、创建时间及钱包余额，并提供修改密码表单；可从侧栏或顶部头像进入。身份资料由管理员维护，用户改密后重新登录。

管理端与用户端的用量记录均将“模型”“接口”拆为两列。“类型”合并传输方式与响应模式，如 http/流式。接口列按“入站:”“上游:”两行显示标准协议路径；未知历史上游显示“—”，不从入站路径猜测。详情同步展示两种接口及合并后的类型。

概览顶部的四个账户／模型数量使用可点击的紧凑入口，桌面为一行，手机为两列。用量摘要同样在手机上采用两列紧凑布局。

已提交的筛选、账户列表的表格／卡片视图、每页条数和概览图表勾选仅保存在当前浏览器的 `codex2api-ui-v1:` 本地偏好中，刷新和返回页面后恢复；尚未查询的输入不会自动成为已应用筛选。筛选按页面及订阅 ID 隔离；账户搜索只缓存已选 ID 与展示标签，不缓存账号资料、凭据、业务编辑表单、记录行或批量操作选择。最近 7 天等相对时间范围在重新打开页面时重新计算。重置筛选后刷新不恢复旧条件；表格／卡片偏好独立保留。读取会校验本地偏好的字段及类型，损坏的缓存回到默认值；浏览器禁止存储时仍能在当前页面使用筛选和切换视图。

管理表格在小于 768px 的屏幕上仍保留原生表格、表头和列对齐，不改成逐条展开的卡片。默认按业务展示 2–4 列，名称／模型、状态、核心数值和操作保持紧凑；长名称截断，点击带箭头的名称打开官方 Dialog 查看完整字段，用量复用请求详情。各表格提供官方 DropdownMenu 的“显示列”设置，可逐列勾选、显示全部或恢复默认，至少保留一列。列偏好按表格及桌面／手机分别保存到浏览器，刷新后恢复，勾选列不触发统计或上游请求。桌面默认完整列，手机默认紧凑列；选择较多列时保留完整表格并使用原有横向滚动。默认一页 20 条用量记录的总行高不超过 1600px。账户列表在手机上固定用表格，桌面保存的卡片偏好保持并在回到桌面宽度时恢复。字段与默认列均由前端定义，详情使用现有真实记录，不额外请求或制造数据；操作和权限检查保持不变。

订阅详情分为账户设置、用量统计、重置卡、记录查询、登录设备五个标签，刷新和返回列表与标签同行。所有可编辑内容集中在账户设置，按账户与订阅、功能开关、个人资料、会话与附件、提示与公告、优惠与定价分类。Desktop、工作区、联系人、站点、侧栏、邀请和赠送等布尔项集中为紧凑的 Switch 列表，不按协议模块各建卡片；每类设置只有一个保存入口，只提交发生修改的配置。未指定的布尔值标为“默认”，保留恢复默认操作，不把未指定写成 false。多项保存中成功项不重复提交，失败项保留修改供重试，继续使用各配置原有的版本校验。测试版、第三方 GPT、额度申请等非布尔选项在“更多功能选项”展开；只有自定义额度申请入口显示说明和链接。常用账户表单和供应号池在宽屏并排；页面表单随页面滚动，只有弹窗限制正文高度。订阅操作、活动日志和客户端记录统一在记录查询中按类别查看，客户端偏好与安装状态保持只读。顶部刷新重读当前页已挂载的资源，保留已显示数据和未提交编辑。

顶部页面搜索支持 `Ctrl/Cmd+K`。账户、套餐、模型和代理列表的查询按钮应用当前筛选，重置清除条件。用户默认无订阅；套餐管理不提供 Free 套餐，也不提供到期兜底。指定模型范围支持搜索、选择当前结果和清除当前结果。代理密码使用“保留／替换／移除”操作，选择替换后才填写新密码，不显示已保存的密码。

主题菜单只提供浅色、深色、跟随系统，默认跟随系统。使用 [shadcn/ui 官方 neutral 配色](https://ui.shadcn.com/docs/theming)，不提供自定义强调色。主题模式仅保存在当前浏览器的 `codex2api-theme`，刷新后保留；清除站点存储后恢复默认。主题不写入后台或同步到业务账户。

按钮、开关、复选框、焦点边框及图表使用官方主题变量；文字、状态、说明与危险操作使用各自的语义样式；用量结果文字固定采用蓝／绿／红区分进行中／成功／失败，不改变主题强调色。数据为空、加载中和操作失败都有明确反馈；不为填充布局生成业务记录。

供应账户的管理员启停与实际可用状态独立。启停操作只保存 `enabled`，不因授权失效、账单受限或额度耗尽而拒绝；列表和详情根据当前回避记录展示正常、停用、授权失效、账单受限、配额耗尽、限流中、过载中或临时回避。重新授权成功自动解除旧失败状态，即使返回相同 Token 也开始新的授权版本，并保留手动停用设置及原账户指纹；无需“检查授权”或手动恢复授权。普通 Token 刷新保留启停和账单状态，迟到的旧请求不能污染新授权。HTTP 401 和明确的永久刷新拒绝标记授权失效；ChatGPT HTTP 402 表示账单受限并退出号池，凭据保留，不因时间经过、额度查询或普通 Token 刷新自动恢复。

供应套餐到期时间在表格中使用独立的“套餐到期”列，卡片、移动端记录详情和账户资料也展示该字段。列表、额度查询和重置状态返回同一字段；ChatGPT 读取已存官方 ID token 的订阅到期声明，不使用 token 自身有效期或额度重置时间代替。官方未提供时显示“—”。

列表只显示供应列表接口附带的 PostgreSQL 额度快照，不逐账户请求 quota，快照缺失或过期也不补查。查询、页面重载、筛选、视图切换和本地倒计时均不触发额度接口或官方请求。列表、卡片和官方额度详情使用同一份窗口摘要，保留官方实际返回的主、次窗口，按 `limit_window_seconds` 展示时长（如 `5h`、`7天`、`30天`），不固定为 5h 和周，也不把 30 天解释为自然月。列表各窗口用两行显示：`5h：2小时后重置` / `进度条 18%`。百分比为已使用比例；不显示“已用”前缀。未返回的窗口不占位；缺少时长的真实窗口显示“主额度”或“次额度”，没有任何窗口时明确显示未提供。失败不清空上次成功缓存，倒计时结束也不伪造用量归零。

供应列表筛选栏不提供刷新按钮；点击“查询”重读本地列表，读取失败保留已有记录并可再次查询。官方额度由后台探测和详情页“从官方刷新”更新。列表“更多 → 重置状态”不请求官方，清除授权失效之外的全部回避记录并失效号池候选缓存，不更改手动停用、授权错误、凭据或官方额度快照。详情查询官方额度后同步重读账户状态。后台独立探测仅覆盖当前额度耗尽的 ChatGPT 账户，每轮结束等待 10 分钟，正常、授权失效及账单受限账户不参与。

图标沿用官方 shadcn 组件默认的 Lucide 线条。Sonner 不启用 richColors，仅将成功图标设为绿色、错误图标设为红色、警告图标设为黄色；文字、背景和边框保持默认主题颜色。

供应列表和卡片的各额度窗口在倒计时旁显示本地周期消耗，如 `$12.34 / 3.80M`，进度条和官方百分比仍放在第二行；详情“本地用量”展示同一组周期统计。周期为 PostgreSQL 官方快照的 `[reset_at - limit_window_seconds, reset_at)`，按本地请求开始时间及供应账户 ID 汇总所有消费来源。金额直接累加账本已结算费用，保留请求时价格，不按当前定价重算；Token 为输入加输出，缓存和推理不重复相加。缺失金额或 Token 显示“未知”，有已知小计时直接显示数值，不追加符号，悬停说明缺失请求数、已知小计与周期边界；缺少周期边界时显示“用量待确认”。过期快照仍保留原周期，收到新的官方快照后再切换，界面倒计时不触发官方请求。用量图表单柱最大宽度为 48px，避免只有一两天时铺满图表。

页面结构由前端固定定义，不能用 loading/data/error 条件决定整个页面、表格或表单是否渲染。表头、筛选栏、详情标签、表单字段和操作区先呈现，接口数据只绑定值和记录行；加载中、失败或没有数据时保留这些结构。保存按钮只在真实数据就绪时可用，不能把占位值写回后端；同一资源刷新失败保留此前数据。账户服务配置和只读记录的栏目／字段定义在 `src/lib/account-fields.ts`，不根据接口下发的字段定义生成界面。表单编辑值与远程初始值分别保存，首次数据到达不通过卸载重建表单填入。


用量页筛选控件和查询操作使用紧凑的单行流式排列，小屏自然换行。用量列为两行文字数值：输入／输出／思考、缓存读取／缓存写入／缓存率；Token 使用 K/M 等单位，悬停显示精确值。缓存率是缓存读取除以总输入，缺失或零分母显示 `-`。耗时按毫秒、秒、分、小时显示，详情遵循同一格式。用量和费用保留实际结算值，缺失时显示 `-`。请求状态显示“进行中／成功／失败”，分别使用蓝／绿／红文字，点击打开官方 Dialog 查看详情。管理端详情顶部在时间右侧以“上游 ID”显示官方 `x-request-id`，无记录时为 `-`；用户端只显示本地请求 ID。模型不一致显示 `请求模型 → 响应模型`，相同只显示一个模型。

概览摘要及图表各分组的缓存率，按当前筛选条件的缓存读取总量除以输入总量计算，不平均单条请求的百分比；个别请求缺失数据不再遮掉已知汇总的比例，缺失计数继续单独保留。总输入为零或完全没有缓存读取数据时显示 `-`。图表底部只保留统计指标图例，具体模型标识在悬浮提示中显示。

## 操作和无障碍

“API 服务”菜单在管理端提供 API 组和 API 密钥，在用户端提供 API 密钥；用户端模型广场位于“工作台”，钱包位于“账户”。所有请求共用管理端用量记录、用户端使用信息及其详情，不提供独立 API 用量页面。用户端与管理端保持相同的紧凑筛选、显示列、手机布局、状态和详情样式；用户端省略供应账户及管理字段。失败请求也展示已经上报的真实用量和费用。“类型”列按客户端请求显示“流式 / 同步”，历史未记录的类型保持未知，不根据上游响应方式推断。模型广场使用响应式卡片展示每个模型，名称旁显示模型平台（厂商）图标，横向标签切换基础计费与公开 API 组。卡片只展示起始档价格，文本优先选标准档的首个输入区间，图像显示最低已配置价格；缺失价格保持待定价。点击卡片查看完整标准价格区间，区间按实际计费阈值显示为不重叠的范围；Fast/Flex/Ultrafast 倍率覆盖该模型的全部标准区间，单独显示“标准价格 × 倍率”，不重复展开单价或设置独立区间，已有独立自定义价格保持显式展示。分组价格使用接口返回的实际计费金额，不展示价格箭头。基础计费不展示分组倍率或调用限制；具体分组的顶部显示组限制，模型卡片头部显示该模型最终生效的基础倍率（模型覆盖优先于分组默认），卡片和详情显示该模型的并发/RPM，0 显示无限。其他计费（ChatGPT 搜索）与模型使用同一卡片网格，展示按次价格，基础目录读取已保存基础搜索价，分组读取自身单价，不再乘组或模型倍率，未配置保持待定价。API 组和套餐编辑共用同一个模型规则表格：勾选即授权，每行可填写模型倍率、每用户并发和 RPM；候选项来自全部平台的计费目录，平台只是标签，可按模型名称和平台筛选候选项。行按计费目录顺序固定，勾选不改变行的位置；已授权但目录不再提供的模型在未选平台且名称匹配时排在候选项之后，便于取消。关联标签可多选且不限平台，标签只配置执行号池。列表和用量使用服务端筛选与分页。

API 密钥绑定一个组，完整秘密仅在创建或轮换结果弹窗中显示一次，不写入浏览器持久存储。密钥只有已启用 / 已停用两种状态；行操作提供编辑（名称、API 组、状态）、启用 / 停用、轮换密钥和删除，轮换与删除各自经确认弹窗执行，删除后密钥从列表移除。密钥列表显示可识别前缀、用量与当前并发；用户只能查看自己的记录。钱包的用量扣费与订单支付、系统调整分别显示来源；使用信息页展示未满一美分及超额的累计待扣费用。访问地址设置区分 OAuth 客户端基础地址与 AI API 网关基础地址。

套餐由管理员填写本地名称和 Markdown 描述；用户端卡片仅展示最多三行描述摘要，不从模型权限或额度拼接介绍文案。点击卡片、名称或“查看详情”打开 Dialog，展示完整 Markdown、平台、售价、有效期、额度规则和具体可用模型；模型表来自套餐授权列表与已启用目录的交集。Markdown 支持标题、列表、链接和表格，忽略原始 HTML。未填写描述时不生成宣传内容。官方客户端订阅档位独立配置，仅用于对应客户端协议；用户端名称仍是本地套餐名。

计费配置提供“模型计费”和“其他计费”两个页签。其他计费中的 ChatGPT“搜索”按次计费，填写每次价格（USD），不使用接口路径作为配置名称；未配置价格保持未知，保存检查修订版本。读取失败保留当前价格并禁用保存，使用 toast 提示。

模型编辑器读取独立的 `/admin/api/models/presets` 预设数据。新建模型输入精确名称时自动填入完整价格，人工修改后不再被自动覆盖；编辑已有模型保留现价，可通过“应用预设价格”明确替换。显示预设来源和核查日期，缺价模型显示“待定价”。Token 标准规则按输入起点划分区间，显示上限取下一起点减一与显式上限的较小值。按倍率配置的服务档位继承全部标准区间；缺失档位保持未定价，独立自定义价格不伪装为倍率。图像模型提供“统一价格”和“按分辨率定价”，统一价格只填写一次每张金额，适用于全部尺寸；两种模式分别保留当前编辑草稿，保存仅提交所选模式。页面结构和价格字段固定在前端，加载失败使用 toast，不能保存未加载的占位默认值。

重置卡发放使用 Dialog，顶部只提供发放按钮和可用数量；配置字段不放在筛选栏。订阅列表通过服务端分页和筛选读取本页数据，同一筛选表达式用于跨页全选，可排除个别账户。额度使用账户本地账本的实际窗口，以倒计时、Progress 和百分比显示；倒计时及视图切换不发起供应查询。

供应账户回调授权步骤显示完整可点击授权地址和复制按钮；普通 HTTP 地址使用选中文本复制作为浏览器 Clipboard API 不可用时的回退。

管理员会话失效或缺失统一返回 HTTP 401 / `unauthorized`，会话存储暂时无法读取返回 HTTP 503 / `session_unavailable`，不能把读取故障解释为未登录。浏览器无法连接后端时使用本地 `network_error`（status 为 0，表示没有 HTTP 响应）；其他后端 5xx 和权限 403 也不清除会话或 CSRF。前端只在确认续期后仍返回 401 / `unauthorized`、主动退出或修改管理员凭据后进入登录界面。首次会话检查遇到连接故障保留当前地址，显示“重新连接”操作并用 toast 提示错误；重试成功后继续原页面。

两端网页使用独立的 access / refresh JWT：access 有效期 15 分钟，refresh 有效期 30 天，均保存于 HttpOnly Cookie。页面可见时每 10 分钟续期，回到页面时补查；请求遇到 401 / `unauthorized` 先共用一次刷新，再重试原请求一次，刷新令牌无效才退出。刷新接口检查本端身份、令牌用途和 CSRF，成功后轮换 refresh 并重新计时 30 天；并发标签页在 30 秒内复用同一次轮换结果。CSRF 通过同路径的可读 Cookie 在重新打开页面时恢复，令牌不写入浏览器存储或 JavaScript 状态。退出、改密和停用撤销整次登录。

用户端刷新时先恢复 HttpOnly Cookie 会话，确认完成前只显示加载状态，不提前渲染登录表单。只有确认无法续期或主动退出后才显示登录页；网络或服务故障通过 toast 提示并提供重连，已取消请求不能触发会话失效。

响应式布局统一按布局视口的 768px 断点切换，不按触屏直接判定手机。手机浏览器开启桌面版/PC 模式（非移动端 UA 且具备触屏/粗指针或移动屏幕特征）时，前端通过 `use-mobile` 持久锁定 1280px 视口与缩放比例（并在忽略动态 meta viewport 的内核中自动回退为根级 1280px 缩放布局），同时固定 `useIsMobile()` 为 `false`，让侧栏、表格和 CSS 断点一致进入桌面布局。普通手机 UA 保持设备宽度；普通电脑缩窄窗口仍可正常进入紧凑布局。

菜单、选择框、对话框、抽屉、标签页与开关使用 shadcn 的 Radix 行为；可输入账户选择使用官方 shadcn Combobox 及其 Base UI 依赖。表单保留具名标签；所有错误使用 Sonner 浮动消息，不插入页面或表单布局，不主动移动焦点。关闭对话框恢复触发位置的焦点。危险操作先呈现确认对话框，取消不写入；提交期间禁止重复操作和关闭弹窗。过渡遵循系统 `prefers-reduced-motion` 设置。

账户身份、订阅、模型价格及服务策略通过真实管理 API 持久化。客户端偏好、审批、会话及安装记录在管理端只读。请求日志按当前账户和筛选条件在服务端分页，显示匹配记录的真实总数。OAuth scopes、CSRF、管理员会话、消费账户隔离和模型授权规则保持独立；供应授权失效、账单受限与额度耗尽按各自恢复规则退出或重返号池，不改变管理员启停设置。

## 开发环境

`pnpm dev` 只启动 Next 开发服务器，Rust 后端需要单独运行。默认管理后端地址为 `http://127.0.0.1:8081`，与 Rust 的默认监听地址一致；也可以连接已有的开发后端。首次构建 Rust 服务请先完成下方的静态构建步骤。

```powershell
cd frontend
Copy-Item .env.example .env.local
# 如后端使用其他地址，在 .env.local 中修改 CODEX2API_DEV_BACKEND_URL。
pnpm dev
```

`.env.local` 仅在首次配置时从示例复制。开发入口为 `http://localhost:3000/admin/`，以终端实际显示的端口为准；开发服务器根路径会临时重定向到 `/admin/`。环境变量修改后重启开发服务器。

`CODEX2API_DEV_BACKEND_URL` 只接受 HTTP(S) 协议、主机与端口，例如 `http://127.0.0.1:8081`；不要附加 `/admin`、API 路径、用户名密码、查询参数或片段。该变量仅在 Next 开发服务器读取，不使用 `NEXT_PUBLIC_`，不会写入浏览器代码或账户配置。实际地址保存在被 Git 忽略的 `.env.local`，`.env.example` 只保留默认示例。

管理前端只代理 `/admin/api/:path*` 到管理后端。用户前端只代理 `/user/api/:path*` 到 `CODEX2API_DEV_USER_BACKEND_URL`（默认 `http://127.0.0.1:8082`）。两个开发服务分别运行 `pnpm dev --hostname 127.0.0.1 --port 3000` 与 `pnpm dev --hostname 127.0.0.1 --port 3001`，入口为 `/admin/` 和 `/user/`。Rust 的 `CODEX2API_PUBLIC_USER_URL` 应设置成用户开发入口 origin `http://127.0.0.1:3001`，以便授权跳转与同源校验一致。规则关闭 Next 的 API 尾斜杠改写，保留 Rust 接口路径。

生产构建仍为 `output: "export"`，不启用开发代理、根路径跳转或开发地址校验，也不增加 Node.js 运行服务。配置依据为 Next.js 官方的[阶段配置](https://nextjs.org/docs/app/api-reference/config/next-config-js#phase)、[外部 rewrites 与 basePath](https://nextjs.org/docs/app/api-reference/config/next-config-js/rewrites)和[尾斜杠控制](https://nextjs.org/docs/app/api-reference/config/next-config-js/skipTrailingSlashRedirect)。

Tailwind 在 `src/app/styles.css` 中通过 `source("../")` 明确只扫描前端 `src/`。不得扫描 `.next` 构建缓存、日志或测试产物，以免把缓存里的字节误识别为任意值工具类并生成无效 CSS。开发回归同时检查浏览器控制台错误与警告，不能只以 TypeScript/ESLint 通过作为运行正常的依据。

两个前端各自的 `scripts/build.mjs` 在导出前后分别计算源码 SHA-256，包含 `components.json`、依赖锁文件、PostCSS 配置、页面、组件和构建脚本。只有文件列表和内容保持一致才生成清单；构建期间改动源码会明确失败，旧清单也不会保留。两个业务 crate 的 `build.rs` 通过 `crates/codex2api-common/src/frontend_build.rs` 使用相同文件集合校验，源码或配置变化后必须重新导出。

Windows 导出后，将 Next 预加载片段中误生成的子目录规范为客户端约定的点分文件名（例如 `usage/__next.usage.__PAGE__.txt`），避免内嵌静态服务的导航预加载返回 404。Linux 已正确导出的文件保持原路径。

## 动态表单选项与用量筛选

概览统计从 PostgreSQL 的用户平台身份及订阅实际用量记录聚合，独立于用量列表分页。顶部提供用户/账户、供应账户、请求／响应模型关键词、请求状态、时间范围和分组筛选。“用户/账户”在同一搜索框中区分普通用户与订阅，选择用户汇总其各平台身份的用量，选择账户仅统计该订阅；可叠加供应账户条件。默认最近 7 天，可选今天、最近 24 小时、30 天或自定义；按小时最多 31 天，其余最多 366 天，采用浏览器提交的本地 UTC 偏移，结束边界不含。概览只保留一张组合图：每个分组以一根柱体按实际模型堆叠输入加输出 Token，同一绘图区默认叠加 Token 用量、请求数、缓存率、费用四条不同颜色的曲线。筛选栏下方的五个勾选项分别控制模型柱体与四条曲线，仅在浏览器切换显示，不发起统计或上游请求；重置恢复全部显示。四种指标保留独立的数值比例，Token 柱体与 Token 曲线共用比例，但隐藏左右数值轴及单位标签。悬停中的 Token 统一用 K/M 等单位，省略完整原始整数；请求数、缓存率和费用保留各自单位。按小时、天、模型或订阅分组时，柱体和四条曲线使用完全相同的分组身份；非时间图表展示 Token 用量前 20 项，摘要保留全部匹配数据。缺失数据仍保持未知值。

统计总 Token 为输入加输出，不重复计入缓存读取或推理 Token；缓存率按缓存读取总量除以输入总量计算，不平均逐请求百分比。存在缺失输入或缓存信息、或输入为零时，缓存率显示 `-`。真实已报告用量（包括失败及客户端停止请求）与已结算费用均保留，缺失值不当作免费或零用量；有已知部分时展示小计及缺失请求数。无记录时间段可补零，有记录但未上报用量的时间段保留未知。图表和摘要结构在加载或失败时保持，刷新失败保留同一查询的已有结果并使用 toast 提示。

动态实体选项从各自资源接口获取，不随业务记录或初始化结果夹带返回：用量接口只返回记录和分页，执行路由只返回路由，套餐只返回套餐，OAuth 初始化只返回指纹，账户配置只返回配置数据。表单候选使用独立的轻量接口：模型选择读取 `/admin/api/models/options`，套餐选择读取 `/admin/api/plans/options`，代理选择读取 `/admin/api/proxies/options`，标签选择读取 `/admin/api/supplier-tags/options`；模型搜索和平台条件由 PostgreSQL 处理；插件与连接器分别读取当前订阅的 `/plugins` 与 `/connectors` 管理接口，保持账户隔离。

用量的供应账户、消费账户及执行路由的供应账户选择直接使用 [shadcn Combobox](https://ui.shadcn.com/docs/components/radix/combobox)，在原输入框键入搜索，下拉只展示匹配结果，不另放搜索框。打开时请求对应 `/suppliers/options?limit=5` 或 `/subscriptions/options?limit=5`；输入经 250ms 防抖后携带 `search`，由 PostgreSQL 对供应账户名称/邮箱、订阅用户名/邮箱执行子串搜索。旧请求取消，客户端不再二次过滤，也不从用量历史构造选项。路由搜索额外传入 `provider_id` 与 `for_routing=true`。已选 ID 独立保存，不因当前搜索结果变化丢失。管理列表统一返回数据库当前页，账户搜索使用独立的候选接口。

用量查询提交 `supplier_id`、`virtual_account`，均精确匹配 ID。状态列与详情共用请求状态：“进行中”使用蓝色、“成功”使用绿色、“失败”使用红色，不将数字协议状态作为结果标签。服务端/上游异常造成的未完成和中断归入失败；客户端停止归入成功，详情注明客户端停止；请求结果由 Responses 终止事件决定，不把连接的 HTTP 200/101 当作生成结果。详情移除“HTTP 状态（连接）”“生成错误状态”“计费状态”和“命中计费挡位”，失败详情显示持久化的 `error_code`，缺失时显示 `-`，不映射为失败类别。管理端失败原因优先显示 `error_message`，其次显示 `error_code`，并显示用户看到的错误码与原因、供应渠道和已恢复的失败尝试；用户端只展示错误处理后的错误码与原因（`error_code`、`error_reason`），不暴露供应原始诊断。两者均缺失时明确提示未保存失败原因，不推断或补造。上游执行仍保留协议错误分类和状态，连接 `http_status` 不作为生成结果。请求速度仅文本请求展示。列表来源只显示 `订阅` 或 `Api`；详情来源显示 `订阅:套餐名` 或 `Api:组名`，名称保留请求开始时的快照；旧记录缺少套餐名时显示 `—`，不使用当前套餐回填历史。“消费”只显示实际扣除金额：API 使用实际钱包扣款，订阅使用本次结算金额，不附加钱包或订阅字样。管理端详情的“成本”展示请求时模型价格快照和实际用量的计算过程，不乘配置倍率；用户端不展示成本。列表费用使用官方 Popover，点击后展示实际费用公式，桌面与手机共用；倍率为 1 时省略括号和倍率项，浮层和成本详情只保留公式，不附加单价单位说明，普通输入扣除缓存读写，思考 Token 不重复计算。图片按数量和单价，搜索按次数和单价展示。缺失快照或用量保留未知，不按当前价格重算历史。

所有查询表单的提交和重置显式调用资源刷新；相同条件、相同页码重复提交也必须重新请求。初次加载及搜索输入防抖不能替代用户主动查询。

请求状态与计费分离：HTTP 响应体由客户端丢弃、WebSocket 客户端结束连接或上游返回取消确认时，记录 `client_stopped`，按已报告的实际用量结算一次。服务端/上游异常必须保存错误原因；服务重启恢复遗留请求时记录 `process_restarted`。缺少上游用量时保留 `missing_usage`，不伪造零用量或估算扣费。

供应账户官方额度、用量、资料和重置额度均按账户与分类写入 PostgreSQL，默认复用 10 分钟快照；进入页面不会请求官方。点击“从官方刷新”才强制刷新，刷新失败时继续显示上次快照并提示错误。供应列表和详情始终以邮箱作为账户主标识，资料页明确显示邮箱，不用官方用户名替代。Grok 订阅优先读取官方用户资料，缺失时补读服务配置中的订阅名称；管理员可显式刷新官方资料并更新账户记录。官方用量统计统一使用 Token 的 K/M 单位，任务时长使用秒、分、小时，图表坐标轴和悬浮提示沿用相同格式。Antigravity 的官方额度每个额度一行（Claude 与 GPT-OSS 共用的额度池一行列出全部模型，Gemini 每个模型一行），列出已用比例与重置倒计时；“同步上游模型”调用官方 `fetchAvailableModels`，按显示名称把推理强度变体与别名合并为一个模型，不写入计费配置；账户资料显示当前有效的模型回避。

所有记录表的总条数、总页数与分页控件统一放在表格底部，移除顶部记录汇总。默认每页 20 条，可选 10、20、30、50 条，切换后回到第一页，条数选项优先向下展开，下方空间不足时自动向上展开，菜单不覆盖按钮；首页、上一页、页码输入、下一页、末页使用官方 Pagination、Button 和 Input，页码可按回车或失焦跳转，非法页码通过 toast 提示。PostgreSQL 先筛选、按稳定顺序排序，再执行 COUNT 与 LIMIT/OFFSET；API 返回 items、total、page、page_size，前端不下载全量记录后 filter/slice。查询或重置回到第一页；账户卡片和表格共用当前页。用量表的“模型”“接口”为独立列，接口以入站／上游两行展示；传输方式并入“类型”；“推理强度 / 速度”独立成列，使用 `xhigh / default` 形式单行显示。

添加供应账户使用“指纹配置 → 授权方式 → 开始授权”三步流程；API 提供商使用“接入配置 → 模型列表 → 确认”：第一步填写名称、线格式、认证头（选项随线格式变化，OpenAI 线格式只有 Bearer）、Base URL、同号重试、代理和一个 API Key，第二步可获取上游模型并选择或输入模型，第三步展示全部配置与模型后确认创建；API 账户的重新授权只更换 Key。指纹读取完成后才能继续；授权方式使用官方 RadioGroup 和 Field 呈现回调链接、设备码、RT 授权三项。前两步保留输入；回调与设备码在进入第三步时发起授权，RT 在第三步提交。返回修改或关闭弹窗会取消已开始的待完成流程；授权失败保持当前步骤并通过 toast 提示。

供应账户按“提供商、上游用户、上游空间”共同确定身份。同一 Team 的不同成员、同一用户的个人与 Team 空间分别保留记录、凭据和指纹；只有同一用户在同一空间重新授权时才复用原记录。详情分别展示只读的“上游用户编号”和“上游空间编号”，订阅类型仍属于当前空间，不按邮箱或套餐名称合并。缺少用户身份或重新授权时身份不一致，通过现有错误 toast 提示，不覆盖原账户。

## 标签号池、模型与请求限制

标签管理使用独立页面和侧栏入口，负责创建、改名和删除。供应账户列表保留标签筛选，选择框位于最左列，支持跨页选择和选择全部筛选结果；“更新标签”按最终勾选集覆盖所选账户的标签，未修改时不提交。账户详情也用勾选框编辑，仅展示同平台标签。列表继续展示标签、当前并发 / 上限和状态，额度窗口的重置倒计时保留。供应账户状态包含正常、停用、授权失效、账单受限、配额耗尽、限流中、过载中与临时回避；上游限流是限时回避并换号，客户端只在本服务自身限制时收到 429。API 渠道账户以创建时填写的名称作为账户名，“指纹与网络”页签显示并编辑接入配置（名称、线格式、认证头、Base URL、同号重试状态码与次数、代理与 Key 尾号），没有官方额度页。

标签筛选提供“全部标签”“无标签”和具体标签；“无标签”只匹配没有任何标签的账户，与搜索、平台和状态条件共同生效，先筛选再分页及批量选择。表格的“标签”“并发”和“套餐到期”独立成列，可通过“显示列”切换；卡片和移动端记录详情使用独立的标签字段。列表和卡片最多直接显示两个标签，超过两个时显示“+”，点击使用官方 Popover 展示全部标签。操作列只保留“更多”菜单，详情入口放在该菜单内，避免账户信息和按钮堆叠撑高记录行。

标签新增和编辑使用 Dialog，列表行只显示标签内容和操作，不内嵌编辑表单。供应筛选按搜索、平台、状态、标签排列，全部位于查询／重置之前，提交后一起生效；切换平台清除草稿中的标签条件。视图使用一个按钮切换卡片／表格。勾选账户后才显示已选数量、更新标签、全选当前筛选结果和清除选择，混合平台不能批量更新标签。套餐弹窗只保留一份取消按钮和一个关闭控件。

顶部同时显示 Codex CLI、Grok Build、Antigravity 和服务版本。Grok 供应订阅名称优先使用官方 `/settings` 的 `subscription_tier_display` 原文；内部档位仅作缺失时回退，不为官方 `Free` 添加产品前缀。ChatGPT 与 Grok 的重新授权均支持单个 RT，复用原指纹并验证原用户／空间身份，失败不覆盖已有凭据。

订阅执行路由只选择“标签号池”，没有分配账户和手动换绑。套餐管理设置 RPM 限制和并发限制，默认 40 和 10；订阅管理可分别留空继承套餐，0 为无限。RPM 和并发限制由套餐和订阅配置。供应账户详情提供“调度”和“可用模型”：调度配置独立并发上限、优先级与负载容量，模型页可同步本账号上游列表，或通过多选 Combobox 勾选、自由输入自定义模型；勾选立即添加，取消勾选移除，不另设添加按钮。候选项包含未启用、未定价的计费模型；这些操作只改变供应模型。所有表单先渲染结构，加载失败保留当前数据但禁用写入。

供应账户列表选中一个或多个同平台账户时显示“更新模型”，混选平台时隐藏。弹窗上方下拉框只负责搜索、勾选或自由输入模型名称，已勾选模型在下方独立表格逐项显示并可移除；列表内部滚动，标题、选择框和底部按钮保持可见。提交后原子覆盖全部所选账户的可用模型，不进行上游同步。导出弹窗支持“直接导出”和“Sub2api 格式”，均生成 JSON，可选择包含代理；下载后保留弹窗显示导出结果。导入弹窗支持“直接导入”和“Sub2api 格式”，同样可选择导入代理，恢复代理认证及账户绑定；列表为空时也能打开导入。结果显示“名称”和“结果”两列，名称使用账户邮箱，不回显凭据。导入、导出弹窗固定高度且不超过屏幕，标题和底部按钮固定，过多内容在内部滚动。

供应订阅及套餐订阅档位显示官方名称，个人 Pro 档位为 Pro 100/200/500；供应订阅也可能显示 Free；本地套餐仅提供 Go、Plus、Business、Enterprise、Edu 等非 Free 档位。套餐自定义名称与官方展示档位分别编辑，客户端协议值在代码中映射。

## 用户与订阅管理

用户管理提供用户名、名称、邮箱、密码重置、登录启停和钱包记录。身份编辑不写入余额；独立的“调整余额”操作选择增加或减少，填写 USD 金额，原因选填，显示参考余额和预计调整后余额。提交只发送增减金额，由后端在事务内按实时余额执行；页面旧余额不能作为扣减校验或覆盖值。用户资料版本只保护身份资料，API 扣费、偿债、订单支付及余额调整均不递增它，因此正常余额变化不触发版本冲突。减少金额仍受实时余额及已发生 API 待扣费用约束，实际调整前后余额以不可变流水为准。每笔记为系统操作，管理记录展示操作人和原因，用户钱包只展示变动前后金额。改密和停用撤销该用户的全部网页与平台设备登录。订阅管理提供表格／卡片与批量操作，首列为用户；“管理”打开该订阅的设置、用量、重置卡、记录和设备。新增订阅选择已有用户与套餐，不另设登录用户名或密码。

订阅管理可显式选择“重新发放，使用当前售价”，重新开始用量周期并保存升级抵扣基准；普通启停不改原计价快照。用户在同一平台可同时持有多个订阅，列表通过用户、套餐、订阅 ID 和到期时间区分。过期记录保留真实套餐与历史，停止执行权益，不切换 Free。套餐售价、购买时长、供应号池、RPM 限制与并发限制由管理员设置；RPM 默认 40，并发默认 10，两项均支持 0 表示不限。用户套餐详情展示套餐限流，订阅页展示各订阅实际生效的限流。订阅设置与原账户详情相同，支持继承或覆盖套餐号池及限流，供应信息只在管理端显示。用户目录仅显示已配置售价且开启“允许购买”的套餐，两项条件在预览、确认和支付时复核；缺失价格或关闭购买均不可见、不可购买。管理员分配不受这两个销售条件限制。

用户端下单采用“预览 → 确认订单 → 支付 → 完成”。点击套餐按钮只调用 `/checkout/preview`；预览中可选择“购买新订阅”或明确的既有订阅，续订／升级绑定选中的订阅 ID；预览显示平台、套餐、购买 / 续订 / 升级、价格、有效期、抵扣、优惠码及实际应付，支付方式目前为 USD 钱包余额。支付方式选项同时显示可用钱包余额。优惠码旁按钮为“使用优惠码”，仅非空（去除空格后）的输入可提交验证；已经使用的优惠码可单独移除。未应用的改动不能直接确认订单。预览失败或过期可单独“刷新预览”，刷新不会自动创建订单或应用尚未确认的优惠码；取得有效预览后再确认。关闭预览不创建订单。点击“确认订单”后才调用 `/orders`，使用同一预览凭证重试不会创建重复订单；之后单独点击钱包支付，成功后展示完成状态。取消 / 超时 / 余额不足 / 套餐变更 / 优惠券失败分别显示对应提示，不以供应路由配置拒绝钱包支付。升级按日均售价比较、按剩余时长补差价，到期时间不变；低价或同价换套餐等待到期。

用户“我的订单”和管理员“订单管理”均提供筛选、分页、支付方式、优惠码和具名费用明细，展示支付截止及支付 / 取消状态；管理员可取消待支付订单，不能伪造支付或修改已付金额。管理员“优惠券管理”使用名称、优惠码、固定 USD 抵扣、最低应付、适用套餐、有效期、总次数和每人次数等具名字段，显示已用与预留数量。停用保留记录，不删除历史；已确认订单保留当时优惠。优惠后的实际价值用作后续升级抵扣，标价仍用于判断升级。

用户 Cookie 与管理 Cookie 分别携带对应会话用途的 JWT，签名密钥分开；两端接口只接收本端会话 JWT，不接收 AI access、refresh 或 ID Token。跨域 POST 被拒绝；Next 开发代理保留浏览器的同源 Fetch Metadata，写入仍必须携带对应 CSRF。授权页先显示已登录用户或在当前链接验证密码，再从该平台可用订阅中下拉选择目标并单独确认；验证身份不会自动授权或建立持久网页会话。管理员凭据、供应账户与供应路由不出现在用户前端。

订单页和订阅管理使用紧凑的单行可换行筛选栏，取消筛选区域的大卡片留白；订单号为文本框，套餐为下拉框，管理端用户为可输入搜索的 Combobox。用户选择按输入防抖请求，最多返回五个候选，选中 ID 不依赖当前候选列表；用户端订单不提供用户选择。查询应用所有条件并回到首页，重置清空全部筛选。订单套餐选项来自对应权限范围的历史订单，停售套餐仍可筛选。订阅筛选保留“显示已到期”。管理端用量页也提供相同的用户选择方式。

管理概览的订阅显示正常数 / 总数，用户数显示当日活跃数 / 总数；数值说明仅放在控件悬停提示中。页面保留必要字段、金额、状态和操作，不堆放说明性长文。

流水管理 `/admin/wallet-entries/` 展示用户的订单支付和系统操作，提供时间范围、用户名搜索选择和来源筛选、分页及显示列。列表和详情展示用户、订单支付 / 系统操作、变动金额、前余额、后余额、时间、操作人、可选原因及关联订单号。管理端和用户端钱包列表均不展示用量扣费，用量费用在统一用量记录中查看。用量记录新增“来源”列和 Api / 订阅筛选，消费账户分别显示 API 名称和订阅用户名。时间由浏览器本地输入转换为 Unix 毫秒，开始含、结束不含。流水只读，金额调整继续通过用户管理进行；不提供改写或删除历史流水的操作。

## 渠道表单与模型规则

渠道业务字段分别位于 `components/providers/chatgpt/`、`components/providers/grok/` 与 `components/providers/antigravity/`；平台选项与名称由 `lib/providers` 的 `providerOptions`／`providerLabel` 统一提供，套餐与订阅表单只列出提供订阅的平台。模型平台是模型的厂商标签，与供应渠道无关：两个前端分别由 `lib/model-platforms` 提供标签，`components/model-platforms/` 提供厂商图标（Lobe Icons，MIT），“其他”及未收录标签显示通用图标。
共享的供应授权步骤仅负责表单状态和操作，不混用授权端点；登录渠道在配置中声明可用授权方式与官方数据分类，API 渠道使用自己的接入配置流程。Grok 与 Antigravity 支持粘贴授权代码或回调 URL，Antigravity 不提供设备码。
RT 批量创建使用 Textarea，一行一个；每条显示真实进度、失败或原账户复用状态，可仅重试失败项。
批量新账户由后端独立生成指纹和安装 ID，原账户重新授权保留身份。

所有筛选下拉框以管理端用量记录表单为准：具名 Field、官方 Select/Combobox、紧凑宽度、
`w-full` 触发器和 `position="popper"`，不增加其他样式或封装。
模型列表不显示“已验证／未验证”或专门针对自定义模型的提示。添加并启用模型后，
按套餐规则供客户端使用；官方文档／API 只提供可选的价格与描述预设。

列表查询覆盖管理端主列表、账户记录、客户端只读集合、官方已缓存记录，以及用户端套餐、订阅、钱包和设备。详情中的设备、远程服务、分析和站点记录独立分页；客户端 JSON 集合通过 PostgreSQL JSONB 集合查询 分页。翻页、筛选和本地倒计时不调用供应商。供应账户批量全选按相同 SQL 条件读取必要的 ID、平台和标签，单次最多 1000 个，跨页选择不依赖当前页记录。

列表查询复用 SQLx prepared statements，全部输入值（含搜索、ID、JSON 路径及 LIMIT/OFFSET）独立绑定。表名、列名及 ORDER BY 由代码固定，API 不接受任意 SQL 结构。COUNT 与当前页读取使用相同筛选和 PostgreSQL REPEATABLE READ 只读事务；空结果保持第一页，删除后越界页归到末页。

语音通话不可用，通话 API 返回明确不支持错误。独立听写设置保持可用。
