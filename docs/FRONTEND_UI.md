# 管理界面

管理网页和消费账户 OAuth 页面位于 `frontend/`，使用 Next.js 静态导出，最终由 `codex2api-web` 嵌入单个 Rust 可执行文件。运行服务不需要 Node.js，也不读取外部前端目录。

## 组件和布局

所有交互控件使用项目内的 shadcn/ui 组件源码，基础样式由 Tailwind CSS 提供。官方组件源码位于 `frontend/src/components/ui/`。业务页面直接导入官方组件；旧 `ui.tsx` 视觉封装、独立导航搜索/主题菜单封装、自定义图表及记录表格封装已删除。请求、表单校验、错误通知和记录映射属于不渲染界面的业务逻辑，放在 `src/lib/`。禁止重新引入自定义控件和手绘组件样式。

管理壳采用官方 `sidebar-07` 的结构，包含侧栏、顶部导航和内容区。保留紧凑的默认控件尺寸、短间距和表格密度；主内容区不重复显示页面标题和说明卡片，刷新、表格／卡片切换及创建等操作全部放在上方筛选栏。桌面可折叠侧栏；窄屏通过抽屉导航。供应账户和虚拟账户保留各自的业务边界，列表提供筛选以及表格／卡片视图。详情使用横向标签页，长表单使用官方 ScrollArea 在弹窗正文中滚动，标题和操作区保持可见。消费 OAuth 页面独立于管理员壳。

虚拟账户详情分为账户设置、用量统计、重置卡、记录查询、登录设备五个标签，刷新和返回列表与标签同行。所有可编辑内容集中在账户设置，按账户与订阅、功能开关、个人资料、会话与附件、提示与公告、优惠与定价分类。Desktop、工作区、联系人、站点、侧栏、邀请和赠送等布尔项集中为紧凑的 Switch 列表，不按协议模块各建卡片；每类设置只有一个保存入口，只提交发生修改的配置。未指定的布尔值标为“默认”，保留恢复默认操作，不把未指定写成 false。多项保存中成功项不重复提交，失败项保留修改供重试，继续使用各配置原有的版本校验。测试版、第三方 GPT、额度申请等非布尔选项在“更多功能选项”展开；只有自定义额度申请入口显示说明和链接。常用账户表单和供应绑定在宽屏并排；页面表单随页面滚动，只有弹窗限制正文高度。订阅操作、活动日志和客户端记录统一在记录查询中按类别查看，客户端偏好与安装状态保持只读。顶部刷新重读当前页已挂载的资源，保留已显示数据和未提交编辑。

顶部页面搜索支持 `Ctrl/Cmd+K`。账户、套餐、模型和代理列表的查询按钮应用当前筛选，重置清除条件。套餐的到期免费访问配置可展开；指定模型范围支持搜索、选择当前结果和清除当前结果。代理密码使用“保留／替换／移除”操作，选择替换后才填写新密码，不显示已保存的密码。

主题菜单只提供浅色、深色、跟随系统，默认跟随系统。使用 [shadcn/ui 官方 neutral 配色](https://ui.shadcn.com/docs/theming)，不提供自定义强调色。主题模式仅保存在当前浏览器的 `codex2api-theme`，刷新后保留；清除站点存储后恢复默认。已移除强调色菜单、状态管理和样式覆盖，并在加载时清理旧强调色偏好；不写入后台或同步到业务账户。

按钮、开关、复选框、焦点边框及图表使用官方主题变量；文字、状态、说明与危险操作使用各自的语义样式。数据为空、加载中和操作失败都有明确反馈；不为填充布局生成业务记录。

供应列表状态为启用、停用、错误。停用是管理员策略；错误记录官方连接失败、鉴权失败或服务端故障，保存在独立的供应健康记录中。客户端请求参数错误、429 额度限制和本地权限拒绝不标记供应故障。“更多 / 恢复账户”必须重新请求官方额度并成功，才能清除当前错误；并发的新错误不会被旧恢复结果覆盖，恢复不会重新启用已停用账户。

列表仅查询 SQLite 快照。额度缺失或超过既有 10 分钟缓存期限时，页面按账户读取缓存接口；该接口按账户加锁并复用有效缓存。筛选、视图切换和本地倒计时不会触发官方请求。列表、卡片和官方额度详情使用同一份窗口摘要，保留官方实际返回的主、次窗口，按 `limit_window_seconds` 展示时长（如 `5h`、`7天`、`30天`），不固定为 5h 和周，也不把 30 天解释为自然月。列表各窗口用两行显示：`5h：2小时后重置` / `进度条 18%`。百分比为已使用比例；不显示“已用”前缀。未返回的窗口不占位；缺少时长的真实窗口显示“主额度”或“次额度”，没有任何窗口时明确显示未提供。失败不清空上次成功缓存，倒计时结束也不伪造用量归零。

图标沿用官方 shadcn 组件默认的 Lucide 线条。Sonner 不启用 richColors，仅将成功图标设为绿色、错误图标设为红色、警告图标设为黄色；文字、背景和边框保持默认主题颜色。

页面结构由前端固定定义，不能用 loading/data/error 条件决定整个页面、表格或表单是否渲染。表头、筛选栏、详情标签、表单字段和操作区先呈现，接口数据只绑定值和记录行；加载中、失败或没有数据时保留这些结构。保存按钮只在真实数据就绪时可用，不能把占位值写回后端；同一资源刷新失败保留此前数据。账户服务配置和只读记录的栏目／字段定义在 `src/lib/account-fields.ts`，不根据接口下发的字段定义生成界面。表单编辑值与远程初始值分别保存，首次数据到达不通过卸载重建表单填入。


用量页筛选控件和查询操作使用紧凑的单行流式排列，小屏自然换行。用量列为两行文字数值：输入／输出／思考、缓存读取／缓存写入／缓存率；Token 使用 K/M 等单位，悬停显示精确值。缓存率是缓存读取除以总输入，缺失或零分母显示 `-`。耗时按毫秒、秒、分、小时显示，详情遵循同一格式。失败记录在列表里的用量和费用显示 `-`，不改变后端的真实结算。状态显示带颜色的状态说明和响应码；点击打开官方 Dialog 查看具体失败原因。详情顶部在时间右侧显示官方 `x-request-id`，无记录时为 `-`。模型不一致使用黄色的 `请求模型 → 响应模型`，相同只显示一个模型。

## 操作和无障碍

重置卡发放使用 Dialog，顶部只提供发放按钮和可用数量；配置字段不放在筛选栏。虚拟账户列表通过服务端分页和筛选读取本页数据，同一筛选表达式用于跨页全选，可排除个别账户。额度使用账户本地账本的实际窗口，以倒计时、Progress 和百分比显示；倒计时及视图切换不发起供应查询。

供应账户回调授权步骤显示完整可点击授权地址和复制按钮；普通 HTTP 地址使用选中文本复制作为浏览器 Clipboard API 不可用时的回退。

管理员会话失效或缺失统一返回 HTTP 401 / `unauthorized`，会话存储暂时无法读取返回 HTTP 503 / `session_unavailable`，不能把读取故障解释为未登录。浏览器无法连接后端时使用本地 `network_error`（status 为 0，表示没有 HTTP 响应）；其他后端 5xx 和权限 403 也不清除会话或 CSRF。前端只在确认 401 / `unauthorized`、主动退出或修改管理员凭据后进入登录界面。首次会话检查遇到连接故障保留当前地址，显示“重新连接”操作并用 toast 提示错误；重试成功后继续原页面。

菜单、选择框、对话框、抽屉、标签页与开关使用 shadcn 的 Radix 行为；可输入账户选择使用官方 shadcn Combobox 及其 Base UI 依赖。表单保留具名标签；所有错误使用 Sonner 浮动消息，不插入页面或表单布局，不主动移动焦点。关闭对话框恢复触发位置的焦点。危险操作先呈现确认对话框，取消不写入；提交期间禁止重复操作和关闭弹窗。过渡遵循系统 `prefers-reduced-motion` 设置。

账户身份、订阅、模型价格及服务策略通过真实管理 API 持久化。客户端偏好、审批、会话及安装记录在管理端只读。请求日志按当前账户和筛选条件在服务端分页，显示匹配记录的真实总数。OAuth scopes、CSRF、管理员会话、消费账户隔离和模型授权规则保持独立；已记录通信故障的供应账户暂停执行，需管理员恢复。

## 开发环境

`pnpm dev` 只启动 Next 开发服务器，Rust 后端需要单独运行。默认后端地址为 `http://127.0.0.1:8080`，与 Rust 的默认监听地址一致；也可以连接已有的开发后端。首次构建 Rust 服务请先完成下方的静态构建步骤。

```powershell
cd frontend
Copy-Item .env.example .env.local
# 如后端使用其他地址，在 .env.local 中修改 CODEX2API_DEV_BACKEND_URL。
pnpm dev
```

`.env.local` 仅在首次配置时从示例复制。开发入口为 `http://localhost:3000/admin/`，以终端实际显示的端口为准；开发服务器根路径会临时重定向到 `/admin/`。环境变量修改后重启开发服务器。

`CODEX2API_DEV_BACKEND_URL` 只接受 HTTP(S) 协议、主机与端口，例如 `http://127.0.0.1:8081`；不要附加 `/admin`、API 路径、用户名密码、查询参数或片段。该变量仅在 Next 开发服务器读取，不使用 `NEXT_PUBLIC_`，不会写入浏览器代码或账户配置。实际地址保存在被 Git 忽略的 `.env.local`，`.env.example` 只保留默认示例。

开发模式把 `/admin/api/:path*` 和 `/api/oauth/chatgpt/:path*` 同源代理到该 Rust 地址，保留原路径、查询、请求体及登录 Cookie。规则使用 `basePath: false`，避免再次添加 `/admin`；同时仅在开发模式关闭自动尾斜杠跳转，避免把 Rust 的 `/admin/api/session` 改成 `/admin/api/session/`。OAuth 页面继续使用 `/admin/authorize/`，授权 API 通过同一个开发代理访问。

生产构建仍为 `output: "export"`，不启用开发代理、根路径跳转或开发地址校验，也不增加 Node.js 运行服务。配置依据为 Next.js 官方的[阶段配置](https://nextjs.org/docs/app/api-reference/config/next-config-js#phase)、[外部 rewrites 与 basePath](https://nextjs.org/docs/app/api-reference/config/next-config-js/rewrites)和[尾斜杠控制](https://nextjs.org/docs/app/api-reference/config/next-config-js/skipTrailingSlashRedirect)。

Tailwind 在 `src/app/styles.css` 中通过 `source("../")` 明确只扫描前端 `src/`。不得扫描 `.next` 构建缓存、日志或测试产物，以免把缓存里的字节误识别为任意值工具类并生成无效 CSS。开发回归同时检查浏览器控制台错误与警告，不能只以 TypeScript/ESLint 通过作为运行正常的依据。

## 构建

```powershell
cd frontend
npm ci
npm run lint
npm run format:check
npm run typecheck
npm test
npm run build
cd ..
cargo check -p codex2api-web
cargo build --release -p codex2api --locked
```

`frontend/scripts/build.mjs` 在导出前后分别计算源码 SHA-256，包含 `components.json`、依赖锁文件、PostCSS 配置、页面、组件和构建脚本。只有文件列表和内容保持一致才生成清单；构建期间改动源码会明确失败，旧清单也不会保留。`crates/codex2api-web/build.rs` 使用相同文件集合校验，源码或配置变化后必须重新导出。

Windows 导出后，将 Next 预加载片段中误生成的子目录规范为客户端约定的点分文件名（例如 `usage/__next.usage.__PAGE__.txt`），避免内嵌静态服务的导航预加载返回 404。Linux 已正确导出的文件保持原路径。

## 浏览器验证

业务浏览器测试调用真实隔离服务。读取失败验收在独立测试浏览器中注入 500 响应，延迟响应验收暂缓接口返回，以检查固定页面结构、同一控件填值与禁用保存；成功读取、管理写入和 OAuth 授权仍使用真实后端。必须先给 `CODEX2API_DB` 配置全新的临时 SQLite，使用随机 localhost 端口启动当前编译产物；禁止指向生产数据目录或重启生产服务。测试数据库可以使用 `review_fixture` 的明确本地验收记录，供应 OAuth 与真实上游推理不属于这轮 UI 验证。

```powershell
cargo run -p codex2api-admin --example review_fixture --locked -- D:/codex-proxy-rs/target/review-next-ui-redesign-20260923/review.sqlite
# 在独立工作目录启动最终二进制，设置 CODEX2API_DB 和随机 CODEX2API_BIND。
cd frontend
$env:CODEX2API_TEST_BASE_URL = 'http://127.0.0.1:<临时端口>'
$env:CODEX2API_TEST_OUTPUT_DIR = '../target/review-next-ui-redesign-20260923'
npm run test:e2e
```

测试覆盖实际管理写入、具名表单、套餐模型范围、消费账户隔离、只读客户端记录、OAuth PKCE 回调和 scope，以及重设计后的导航、视图切换、筛选、确认操作、长弹窗和响应式布局。主题验证使用两个独立浏览器上下文，检查刷新保留、互不影响、跟随系统、旧强调色清理、清除后恢复默认及没有后台写入。截图保存在隔离输出目录的 `screenshots/`，Playwright 失败记录保存在 `playwright-results/`。验证结束后停止本次临时服务。

## 动态表单选项与用量筛选

动态实体选项从各自资源接口获取，不随业务记录或初始化结果夹带返回：用量接口只返回记录和分页，执行路由只返回路由，套餐只返回套餐，OAuth 初始化只返回指纹，账户配置只返回配置数据。模型选择读取 `/admin/api/models`，套餐选择读取 `/admin/api/plans`，代理选择读取 `/admin/api/proxies`；插件与连接器分别读取当前虚拟账户的 `/plugins` 与 `/connectors` 管理接口，保持账户隔离。

用量的供应账户、消费账户及执行路由的供应账户选择直接使用 [shadcn Combobox](https://ui.shadcn.com/docs/components/radix/combobox)，在原输入框键入搜索，下拉只展示匹配结果，不另放搜索框。打开时请求对应 `/suppliers?limit=5` 或 `/consumers?limit=5`；输入经 250ms 防抖后携带 `search`，由 SQLite 对供应账户名称/邮箱、虚拟账户用户名/邮箱执行子串搜索。旧请求取消，客户端不再二次过滤，也不从用量历史构造选项。路由搜索额外传入 `provider_id` 与 `for_routing=true`。已选 ID 独立保存，不因当前搜索结果变化丢失。无搜索参数的完整管理列表接口保持原有行为。

用量查询提交 `supplier_id`、`virtual_account`，均精确匹配 ID。状态列同时显示状态说明与 HTTP 状态码：进行中蓝色、成功绿色、失败红色；筛选、列表和详情共用这三种状态，服务端/上游异常造成的未完成和中断归入失败；客户端停止归入成功，详情注明客户端停止；流式请求即使 HTTP 为 200，也按实际完成状态显示失败。具体错误原因仅在请求详情弹窗展示。

所有查询表单的提交和重置显式调用资源刷新；相同条件、相同页码重复提交也必须重新请求。初次加载及搜索输入防抖不能替代用户主动查询。

请求状态与计费分离：HTTP 响应体由客户端丢弃、WebSocket 客户端结束连接或上游返回取消确认时，记录 `client_stopped`，按已报告的实际用量结算一次。服务端/上游异常必须保存错误原因；服务重启恢复遗留请求时记录 `process_restarted`。缺少上游用量时保留 `missing_usage`，不伪造零用量或估算扣费。旧 `interrupted` 记录没有可靠结束来源，不能追溯假定为客户端停止。

供应账户官方额度、用量、资料和重置额度均按账户与分类写入 SQLite，默认复用 10 分钟快照；进入页面不会请求官方。点击“从官方刷新”才强制刷新，刷新失败时继续显示上次快照并提示错误。授权完成后会读取一次官方资料并把用户名写入供应账户的官方资料快照，详情页优先读取这个持久化用户名。官方用量统计统一使用 Token 的 K/M 单位，任务时长使用秒、分、小时，图表坐标轴和悬浮提示沿用相同格式。

所有记录表的总条数、总页数与分页控件统一放在表格底部，移除顶部记录汇总。默认每页 20 条，可选 10、20、30、50 条，切换后回到第一页，条数选项优先向下展开，下方空间不足时自动向上展开，菜单不覆盖按钮；首页、上一页、页码输入、下一页、末页使用官方 Pagination、Button 和 Input，页码可按回车或失焦跳转，非法页码通过 toast 提示。完整列表先筛选再分页，查询或重置回到第一页；账户卡片和表格共用当前页。用量表的“模型 / 接口”为两行，接口与传输方式在同一行；“推理强度 / 速度”独立成列，使用 `xhigh / default` 形式单行显示。

添加供应账户使用“指纹配置 → 授权方式 → 开始授权”三步流程。指纹读取完成后才能继续；授权方式使用官方 RadioGroup 和 Field 呈现回调链接、设备码、RT 授权三项。前两步保留输入；回调与设备码在进入第三步时发起授权，RT 在第三步提交。返回修改或关闭弹窗会取消已开始的待完成流程；授权失败保持当前步骤并通过 toast 提示。
