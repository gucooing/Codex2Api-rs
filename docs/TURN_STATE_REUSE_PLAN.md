# 正常流量 state 采集与复用

## 最终行为

按用户要求移除所有辅助探针，仅处理真实的 HTTP Responses 请求。不开定时任务，不生成测试 prompt，不产生额外上游请求。默认关闭；每个账户独立设置模型列表和 TTL。

请求路径在 `codex2api-upstream/src/client.rs` 的 `forward_to` 完成请求规范化后进入 `turn_state.rs`。模型元数据通过支持 zstd 的解码函数读取；不将压缩后的字节直接当作 JSON。

1. 功能关闭、模型不匹配或 `generate=false`：按现有逻辑透传，不参与采集。
2. 客户端 state 合格：保持当前请求头，允许更新缓存；即使缓存有效，也不覆盖正常客户端 state。时间更旧但仍合格的客户端 state 仍可透传，只是不使缓存回退。
3. 客户端 state 缺失、不合格或过期：有有效缓存时替换请求头；无有效缓存时保持原请求透传，等待正常流量采集。
4. 正常上游返回 HTTP 200：在收到响应头时检查 state，合格则缓存。时间较旧的 state 不覆盖时间较新的缓存。
5. 缺失、不合格 state、非 200 响应或网络失败：记录诊断，不覆盖缓存。正常响应 body 不被读取、缓冲或替换。

已经发往上游的并发请求不会被追溯修改；缓存提交完成后开始的匹配请求只在客户端 state 缺失或不合格时使用缓存。

## 筛选与失效

目标筛选沿用 10 块策略：URL-safe Base64（支持有/无 padding），版本字节 0x80，解码长度 `57 + 16 * 10`，有效时间戳，不超前超过 30 秒。可用截至 `issued_at + TTL - 30`。这是不透明 state 的本地结构检查，无法验证签名或证明实际路由及模型质量。

缓存键由代理账户 ID、模型、上游账户身份及配置 revision 限定。不跨账户分享。保存设置、手动清除、授权更新、上游账户身份/代理/HTTP 指纹变更会失效旧缓存；旧 revision 的在途响应不能重新写回。

“保活”指通过正常流量中的新 state 更新缓存，不发送额外请求。后续客户端请求或 HTTP 200 正常响应中的合格 state 可以更新缓存。反复观察到相同时间戳不会延长其有效期；时间更旧的响应不能使缓存回退。过期后仅等待正常流量再次采集，不触发其他请求。

## 存储与管理页面

v0.0.6 的迁移 0016 重建可丢弃的旧缓存表，保留账户、授权、设置等持久数据；不修改已发布的 0015。升级后旧缓存和计数清零，旧配置中的续期、冷却字段不再使用，下一次保存时移除。v0.0.7 仅调整选择策略，无新迁移，升级保留现有缓存和统计。

页面只提供启用、模型列表、TTL，移除探针开关、探测状态、冷却和续期字段。展示缓存来源、采集时间、剩余有效期、请求/响应计数、采集次数、缓存使用次数，以及最后一次请求/响应的诊断、HTTP 状态、state 长度和块数。永不输出完整 state。

“HTTP 请求完成”与“包含合格 state”分别展示。未携带头、编码异常、结构异常、块数不符、过期、时间超前、HTTP 错误都有明确结果，不再统一显示“等待采集”。状态页面通过刷新链接更新。

## 验证范围

本地回环 HTTP 测试通过真实 `forward_to` 入口检查规范化、zstd 请求体和模拟上游实际收到的请求头，覆盖客户端/响应采集、正常客户端 state 透传与缓存更新、仅异常/缺失 state 使用缓存兜底、账户与模型隔离、默认关闭、缺头、非目标、过期、HTTP 失败、清除及未完成 SSE 下的即时采集。

SQLite 测试覆盖并发新旧响应、持久化、授权/身份/设置失效、在途写回隔离。迁移测试覆盖旧版数据库升级与重复打开。管理路由测试覆盖登录、CSRF、配置校验、状态显示及令牌不泄露。

上述验证不调用真实 OpenAI 上游，不能证明真实服务一定返回符合条件的 state，亦不能证明回答质量改善。
