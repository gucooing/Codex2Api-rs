# Turn-state 复用实验实施说明

实现日期：2026-09-19。

## 目标与证据

参考 csss，在本进程内提供按账号隔离的 state 采集、缓存、注入和续期，
用于验证跨 turn 复用是否影响实际任务表现。功能名使用“实验性 turn-state 复用”，
不以“避免降智成功”描述格式校验或注入成功。

- [csss 实现](https://github.com/tzf1003/csss/blob/main/codex-state.js)：
  `parseState` / `acceptState` 按封装、块数和时间筛选；`renew` 发短探针；
  `finishRequest` 注入请求头。默认 10 块、TTL 3600 秒、提前 600 秒续期。
- [固定官方版本](https://github.com/openai/codex/blob/a8964cb1bad67bc26a826fb07d1bef99c6a3f008/codex-rs/core/src/client.rs#L244-L271)：
  state 用于同一 turn 的黏性路由，明确禁止不同 turn 复用；认证归属变化应清除。
- 292/312 是示例令牌的编码长度，不是 HTTP 状态码或已证实的质量等级。
  时间戳与块数检查不是密码学验签；60 分钟是实验策略，不是已证实的服务端承诺。

协议例外仅限：显式开启实验后允许同一账号、同一模型跨 turn 复用 state。
已在 AGENTS.md 中记录这一默认关闭的实验例外。该请求不涉及升级 Codex 基线。

## 首版行为

1. 默认关闭，按账号开启；模型为明确配置的白名单。按解码后的请求正文识别模型，
   支持已有 zstd 路径，不靠可能缺失的模型头推断。
2. 仅处理普通 HTTP Responses 生成；排除 compact、input_tokens、guardian、搜索、
   图像、realtime 和 Responses 子路径。WebSocket 首版不参与实验、不主动中断；
   管理界面说明该范围，使用 HTTP 客户端才能验证效果。
3. 缓存键使用认证后解析的内部账号 ID、ChatGPT 账号身份和模型，
   不信任调用者提供的账号头，不设共享 default 缓存。SQLite 保存 state 与生命周期字段；
   账号删除级联清理，重新授权、令牌刷新、身份/指纹/代理绑定变化和相关配置修改时失效旧缓存。
4. 正常客户端请求携带合格 state 时立即保存；正式回答响应头返回合格 state 时也被动保存。
   正式回答仅观察响应头；不读取或等待完整回答，维持原有流式转发。
5. 没有可用缓存时请求照常发送，不等待探针。探针仅作为可选辅助采集手段，
   使用该账号独立的认证、HTTP 客户端和既有代理，不复制用户正文；不得阻塞用户请求。
   HTTP 200、完整 SSE 完成事件及封装/时间规则同时满足才接受。
6. 默认采用 csss 的 10 块、3600 秒 TTL、提前 600 秒续期，预留 30 秒过期余量。
   同账号/模型同时最多一个探针；探针有总超时和响应大小上限。
   其他并发请求有有效旧缓存则复用，否则直接转发，不等待已有探针。
   冷却期间不反复探测；429 遵循 Retry-After，401/403 延长冷却。
7. 仅替换缺少客户端 state 的请求头；调用者已经携带的 state 优先原样透传，
   避免覆盖其正在进行的 turn。后台清楚区分“缓存可用”“实际注入”和“客户端值优先”。
   这比 csss 无条件覆盖更保守，可能减少实际参与实验的请求数量。
8. 续期失败时旧缓存仅在有效期内可用；无可用缓存则正常转发。
   不因 state 形状变化额外重放正式生成请求。连续两次返回不合格 state 可触发后续刷新，
   但不把令牌值不同直接等同于路由失败或质量下降。
9. 管理界面仅展示长度、块数、剩余策略期限、探针结果与实际注入计数，
   不输出完整 state、认证头或用户内容。探针状态单独展示，不计作用户请求用量；
   不提供探针 token 消耗统计。保存配置或清除缓存也会清除注入计数。

## 验证与验收

- 单元测试：格式边界、时间边界、模型匹配、冷却和配置兼容读取。
- 本地模拟上游集成测试：双账号/双模型不串值、并发请求不等待探针、
  正常响应 state 被动缓存、正式响应不被探针处理阻塞、客户端 state 优先、
  默认关闭及非目标端点/WebSocket 行为保持不变。
- 存储测试：升级现有数据库、重启读取、失效清理、删除账号清理。
- 管理端验证现有会话认证与 CSRF，并确认状态页面不会泄露 state。
- 对修改的 crate 执行 `cargo check -p <crate>` 及相应测试、`git diff --check`。
- 模拟测试只能证明代理行为正确。质量收益需要另行做固定模型、推理参数、
  网络条件和题集的随机对照实测；实现验收不宣称已验证“避免降智”。

## 管理端入口

账户详情的“状态复用（实验）”标签。保存和清除操作均要求管理员会话及 CSRF。
状态通过“刷新状态”按钮更新，不会自动覆盖正在编辑的表单。
仅 HTTP Responses 生效；WebSocket 用户不会因为开启开关而自动获得实验注入。
